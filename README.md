# US EPR Policy Tracker

A static web tool that presents United States packaging Extended Producer Responsibility (EPR) bills and laws in a browsable, filterable interface. Sourced live from the Sustainable Packaging Coalition / GreenBlue EPR Policy Database.

Repository: https://github.com/rbndchsn/US_EPR_Database2026
Live site: https://rbndchsn.github.io/US_EPR_Database2026/

## What it does

The site loads three JSON files at runtime: `data/policies.json`, `data/aggregates.json`, and `data/fields.json`. Those files are produced by a Python script that fetches the latest dataset directly from SPC's public Next.js data endpoints. There is no Excel file in the loop.

Views provided: a home dashboard with status and state pie charts, a Browse view with status / state / year / free-text filters, a per-bill detail page that renders every populated SPC provision category as a collapsible section card, a compliance Deadlines view aggregating registration, plan submission, and implementation dates from passed and amended laws, and an About page explaining EPR and the elements tracked.

## How the data refresh works

1. `scripts/fetch_spc.py` fetches `https://epr.sustainablepackaging.org/policies` to discover the current Vercel build id (it rotates on every SPC redeploy).
2. It then fetches `https://epr.sustainablepackaging.org/_next/data/<buildId>/en-US/policies/export.json` (one request, ~1 MB) to get all policies with full provision-level data.
3. It writes the three data JSON files into `data/`.
4. The static HTML/JS reads those files via `fetch()` at runtime.

The fetcher uses only the Python standard library (`urllib`, `json`, `re`). No `pip install` step is needed.

## Run locally

```bash
# refresh data
python3 scripts/fetch_spc.py

# serve the site
python3 -m http.server 8080
# open http://localhost:8080
```

Opening `index.html` directly via `file://` won't work because the app uses `fetch()` for the JSON files; you need a local HTTP server.

## Deploy and refresh schedule

The included GitHub Action (`.github/workflows/deploy.yml`) runs on three triggers:

1. Every push to `main`
2. A daily cron (06:00 UTC, about 02:00 EDT / 23:00 PDT)
3. Manual via the Actions tab ("Run workflow")

Each run fetches the latest data from SPC, writes the JSON files, and deploys the site to GitHub Pages. The site is therefore at most one day out of date with SPC's source.

## Updating the site code

Edit `index.html`, `assets/`, or `scripts/` in your editor of choice, commit, push. Data is regenerated by the workflow on every push.

## Custom domain (optional)

To use a custom subdomain, add a `CNAME` file at the repo root containing the subdomain (e.g. `epr.example.com`) and configure the DNS CNAME record at your registrar.

## Data attribution

Source: Sustainable Packaging Coalition / GreenBlue EPR Policy Database, https://epr.sustainablepackaging.org/policies. The tracker presents the source data in an alternative interface; consult the SPC database for the authoritative content.
